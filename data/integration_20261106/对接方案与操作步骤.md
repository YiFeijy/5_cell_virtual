# 表达响应与细胞功能数据的对接方案

最新实际完成情况请先读[数据内容 处理步骤与设计原因](../investigation_20261106/当前对接说明_数据内容处理步骤与设计原因.md)。核心HMS关系现按实际库板保留为[v2结果](v2_库板来源核对/README.md)。本文件保留初版设计与较宽的候选试算，其中初版LJP范围包含的78条其他库板签名在v2中另行保存。

日期：2026年11月6日。

本方案对应三个研究问题：由细胞背景和给药条件联合预测表达与功能；研究表达中与功能变化相关的成分；研究早期表达对后期表达和功能预测的价值。以下“建议”是本项目的实施选择，“实际核查”是现有文件的检查结果，文献先例在相应段落给出出处。

## 1 建议采用的总体路线

建立三个互补的数据部分：

1. **同项目核心配对。** 用CCLE背景、LINCS表达、HMS细胞计数，先组织条件对应清楚的3h表达、24h表达和72h功能数据，验证联合预测和时间信息价值。
2. **跨库条件扩展。** 先做LINCS—CTRP，再加入PRISM、GDSC，增加细胞、药物和剂量覆盖；分别记录相同浓度、邻近浓度、曲线内插值三种对应方式。
3. **有各自标签的补充数据。** 表达数据按表达任务训练，功能数据按相应功能任务训练，通过共同的细胞背景、药物结构和条件表示共享信息。

数据对接首先统一实验身份、建立观测之间的关系，随后再组织训练样本。表达和功能保留独立的数值、时间、测量方法和来源。

## 2 同项目核心配对怎样操作

### 2.1 匹配键与数据结构

HMS—LINCS核心关系使用：

`同一Joint Project + 细胞身份 + BRD药物ID + 数值剂量`

表达测量时间另列为3h或24h，功能终点另列为72h。它们对应同一给药条件下的平行实验。

实际核查中，8,337条已读取的LINCS签名所引用的24,819个实例，其细胞、药物、数值剂量和时间与签名条件一致。HMS的六个剂量0.04、0.12、0.37、1.11、3.33、10 μM，与这些实例的数值剂量一致。

已有3,835个条件同时具有3h、24h表达和72h功能；再要求当前CCLE基线与可解析SMILES后，候选核心队列为3,168个条件、5个细胞系、106个药物。表达技术质量、结构身份与逐批次实验设计继续作为入组检查。

### 2.2 一条真实条件如何连接

| 项目 | 本地文件中的实际记录 |
|---|---|
| 细胞 | BT20，DepMap ModelID为ACH-000536 |
| 药物 | afatinib，BRD-A58767537 |
| 剂量 | 0.04 μM |
| 背景输入 | CCLE 24Q4中该ModelID的表达行，按Entrez ID提取978个landmark基因 |
| 3h表达 | LJP006_BT20_3H:G24对应的978维L5签名 |
| 24h表达 | LJP006_BT20_24H:G24对应的978维L5签名 |
| 72h功能 | HMS三个生物重复的相对细胞数量，等权均值约0.7512 |
| 功能重复信息 | 三批均值的标准差约0.0247；每批技术孔记录单独保留 |

这条记录可组织成：

`输入：BT20背景表达 + afatinib结构 + 0.04 μM`

`标签：3h表达签名、24h表达签名、72h相对细胞数量`

第一版功能主标签建议采用HMS的`Relative Cell Count`，辅助标签采用`Relative Growth Rate After Treatment`。后者在本地表中对应相对净增长`(Nt−N0)/(Nc−N0)`，使用`relative_net_growth`命名。两类功能值分别保存。

### 2.3 重复与损失计算

先在每个生物重复内平均技术孔，再对生物重复等权汇总，保留每批值、重复数和标准差。第一版沿用等权汇总，重复间差异用于质量分层和稳健性分析。

每个核心条件只保存一份72h功能终点；3h和24h表达分别关联到这个终点。组织训练批次时，一个条件预测两个表达时间点，并计算一次功能损失。

目前已导出：

- [核心条件表](HMS_core_condition_manifest.csv)：3,168行。
- [表达与功能关系表](HMS_expression_function_relations.csv)：6,336行，分别对应两个表达时间点。
- [功能生物重复表](HMS_core_functional_biorepeats.csv)：9,504行。
- [实例条件核对](HMS_LINCS_instance_condition_verification.csv)：24,819个引用。

这些表保留来源签名ID。一个条件—时间点有多条签名时，先保存签名集合，按实验板和重复结构决定表达汇总方式。关系表中的0.5权重用于示意同一个功能终点被两个时间点引用时的权重归一，并非生物学置信度。

同项目表达与功能平行测量的研究依据见[Niepel等2017年研究](https://doi.org/10.1038/s41467-017-01383-w)。本轮核查细节见[核心关系摘要](HMS_relation_pilot_summary.json)。

## 3 跨库扩展怎样做

### 3.1 第一步统一细胞身份

建立一个细胞身份表，保留原库ID、原名、DepMap ModelID、Cellosaurus RRID、供应商目录号，以及亲本/改造/耐药株信息。

建议顺序为：稳定ID直接对应；来源中的供应商和目录号核实；唯一名称对应生成候选，再核对RRID和细胞背景。名称处理用于找候选，原始名字始终保留。

本轮LINCS—CTRP覆盖试算使用“规范化名称在DepMap中唯一”的候选映射，并导出LINCS目录号与DepMap目录号的一致性字段。覆盖数字属于候选结果；稳定身份核验后，再生成发布给训练流程使用的映射表。

### 3.2 第二步统一药物身份

保留原药物ID和批次ID，建立独立的化学实体ID。对每条结构保存原始SMILES、完整立体化学结构、标准化母体结构、InChIKey和处理记录。

本轮试算先要求相同Broad ID，再用RDKit比较结构：先比较保留立体化学的规范SMILES，再比较经过Cleanup、FragmentParent、Uncharger处理的母体结构。没有执行去立体化学或互变异构体合并。

这一步发现五种药物存在跨库结构记录差异，包括linsitinib、sildenafil、tretinoin、curcumin、methylstat。它们进入结构复核表，逐项区分盐型、立体信息、互变异构与注释差异。结构标准化记录和RDKit版本随结果保存。

CTRP作者明确标为固定比例组合的49个条目另存，当前单药扩展使用其余条目作为候选范围。

### 3.3 第三步对应剂量

浓度统一为μM，保存原值和单位；药物处理的输入特征另计算`log10(dose_uM)`。零剂量对照用独立对照标记表示。

**方式一：相同数值浓度。** 核对细胞和药物后，寻找相同数值浓度的实测功能点。浮点比较采用相对容差1e-6、绝对容差1e-9 μM，这用于处理数值表示误差。

**方式二：有界邻近浓度。** 为每个表达剂量，在同细胞、同药物、同一条功能曲线中寻找最近浓度，并保存：

`剂量差 = abs(log10(表达剂量) − log10(功能剂量))`

建议分别报告0.05、0.1、0.2三档，约对应1.12、1.26、1.58倍浓度差。邻近浓度数据的功能值继续对应原实测浓度，关系表记录它与表达浓度的差别。

**方式三：曲线内插值。** 在功能实验的实测浓度范围内，用两侧实测点或通过质量检查的剂量曲线，估计表达剂量处的功能值。建议先比较log剂量线性内插和剂量曲线拟合，以留出浓度点的误差选择实现。保存两侧浓度、曲线范围、方法和误差，标签标记为`interpolated`或`fitted`。

前两种方式的标签仍来自已有浓度的实测汇总；第三种方式产生目标剂量处的估计值。三类结果分别评估。

Szalai等的公开代码按同细胞、同Broad ID选择最近log浓度，采用差值小于0.2的规则：[作者原始预处理代码](https://github.com/bence-szalai/Cell-death-signatures/blob/master/code/cell_death_1_preprocess.ipynb)。scTherapy使用Cellosaurus匹配细胞，并将LINCS浓度对应到PharmacoDB曲线以取得插值功能标签：[2024年原始方法](https://doi.org/10.1038/s41467-024-52980-5)。本项目建议把这两种路线与精确浓度子集一起比较。

### 3.4 现有文件实际能对应出多少候选

本轮读取了LINCS Phase I、II的签名及实验剂量说明，并读取CTRP 2015的实测浓度表。下表要求Broad ID一致、结构记录相符；细胞身份使用上述唯一名称候选映射。表达范围为3h、6h、24h。

| 剂量对应规则 | 候选表达条件 | 候选细胞模型 | 药物 | 涉及功能曲线 |
|---|---:|---:|---:|---:|
| 相同数值浓度 | 100 | 10 | 17 | 97 |
| log10剂量差≤0.05 | 4,403 | 46 | 222 | 1,981 |
| log10剂量差≤0.1 | 14,578 | 48 | 314 | 6,803 |
| log10剂量差≤0.2 | 19,766 | 48 | 322 | 7,111 |
| 表达剂量落在功能实测范围内 | 20,001 | 48 | 322 | 7,170 |

“表达条件”按发布版本、候选ModelID、药物、剂量、时间计数。两个发布间的重复来源、细胞身份和表达质量筛选会进一步调整规模；同一功能曲线可关联多个表达时间和浓度。因此这些是覆盖候选计数，各规则也互相嵌套。

Phase I剂量使用数值`pert_dose`；Phase II剂量使用签名引用实例的数值字段。试算中有115条Phase II候选签名的实例剂量未能统一解析，已[单列供复核](LINCS_GSE70138_unresolved_dose_instances.csv)。

当前输出的是最近实测点及曲线范围，没有生成插值活性标签。结果见[逐规则覆盖](LINCS_CTRP_coverage_by_matching_rule.csv)、[候选关系](LINCS_CTRP_nearest_measured_candidates.csv)、[药物身份核对](LINCS_CTRP_drug_identity_candidates.csv)。

### 3.5 第四步保留独立的时间和功能测量方法

统一关系表至少有`expression_time_h`和`functional_time_h`两个字段。举例，24h表达与72h活性关联后，两个时间仍分别为24和72。

CTRP功能时间72h来自原实验方案，原表没有逐行时长；本轮关系表已标明此时间依据。GDSC也采用官方方案中的药物暴露时间，并保留原始`DURATION`字段。给药时间与铺板计时在说明中分别记录。

每种功能读数保留自己的定义：HMS相对细胞数量、HMS相对净增长、CTRP的ATP相关相对活性、PRISM的条形码丰度log2变化，以及GDSC的归一化读数。建议按读数设置输出和校准，再评估可共享的部分。

## 4 各数据集分别如何进入流程

| 数据 | 对接操作 | 形成的记录 |
|---|---|---|
| CCLE / DepMap | ModelID对应细胞，按Entrez ID提取978基因；按训练规则拟合标准化参数 | 细胞背景输入及来源Profile记录 |
| LINCS L5 | 基因ID统一为978个实测landmark，保留签名和原实例、剂量、时间 | 表达响应标签；有功能对应时建立关系 |
| LINCS L3 | 以同细胞、同时间、同板或实验设计明确的vehicle为参照，核对重复和控制质量 | 同平台表达与同期参照；便于状态表征比较 |
| HMS | 保留孔、板和三批重复，汇总终点数量及净增长；按LJP细胞、药物、剂量对应表达 | 核心平行测量队列 |
| CTRP | 实验ID到细胞、化合物ID到Broad及结构；提取实测`cpd_avg_pv`，保留每条曲线 | 浓度级功能记录；精确/邻近/内插关系 |
| PRISM | DepMap ID对应细胞；保留完整Broad样品ID、浓度和screen；核对STR标记及重做筛选 | 相对丰度功能记录及曲线；扩展功能监督 |
| GDSC | 通过Sanger ModelID、COSMIC及DepMap说明对应细胞；药物结构映射；按官方流程做板级归一化 | 相对活性及曲线；扩展和跨平台验证 |
| MIX-seq | 按DepMap ID、药物、剂量、时间、生物重复分组，汇总原始计数后归一化 | 条件级表达与细胞分布；附带药敏表单独保留来源 |
| sci-Plex | 依据细胞与处理注释分组，使用人类基因、原生对照和重复；统一药物结构与单位 | 单细胞响应分布及条件级表达 |
| NCI TPW | 探针映射到基因；核对同细胞、药物、浓度下的2/6/24h及对照 | 多时间点表达条件关系 |
| Novartis DRUG-seq | 根据逐孔Annotation和化合物说明对应U2OS、结构、四剂量、24h和重复板 | 表达侧补充；共同药物与条件的对照分析 |
| Tahoe | 映射Cellosaurus ID、药物和样本剂量；依据gene metadata解码整数基因ID，按板找对照 | 大规模单细胞表达补充；当前先使用本地分片 |

单细胞汇总建议采用“同细胞系或类型、药物、剂量、时间、生物重复内先求原始计数和，再进行适合该平台的归一化”，并保留每组细胞数量。比较最低细胞数10、20、50的敏感性，再确定主分析要求。

MIX-seq作者提供的`sens`来自GDSC/PRISM曲线。若模型训练已使用这些相同曲线，外部检验的表达数据与功能数据分别标记来源关系，选择标签独立的部分评价功能泛化。

## 5 只有一种标签的数据怎样使用

建议采用按标签计算损失的多任务训练：

- 有表达的观测，计算表达预测损失。
- 有HMS细胞数量的观测，计算该功能读数损失。
- 有CTRP、PRISM或GDSC功能的观测，计算各自测量类型的损失。
- 同项目配对条件，同时提供表达和功能监督，并用于检验两者关系。

各任务按有效观测数分别求平均，再设置任务权重，控制大规模功能数据与表达数据的训练贡献。缺失标签用mask表示，预测值另存为模型输出。

细胞背景、药物结构、剂量等可共享表示；测量来源、功能类型及时间作为条件或任务分支处理。MultiDCP提供了整合不同资源、联合预测剂量相关表达和功能的先例；它的功能标签包含曲线拟合生成值。本项目第一版建议从已下载的实测浓度级标签起步，拟合标签单独比较。[MultiDCP原始研究](https://doi.org/10.1371/journal.pcbi.1010367)

## 6 初始状态与时间关系怎样定义

建议把两类参照明确命名：CCLE作为跨实验的细胞背景；LINCS L3的同期vehicle作为同平台参照状态。它们各自保留量纲，分别进行标准化和输入比较。L5作为表达变化监督，L3作为归一化表达状态，分别组织实验。

时间部分先开展两个可检验的任务：

1. 用实测3h表达和给药条件预测24h表达、72h功能，检验早期表达的信息价值。
2. 用模型从背景和给药条件预测的3h表达，再预测后续终点，检验完整预测链。

第二种任务中的预测中间状态，应由训练外预测或对应训练折模型产生，保持测试样本的实测后期信息只用于评价。Phase I的6h→24h和NCI的2h→6h→24h作为后续时间扩展。

每条时间关系保留细胞、药物、剂量、参照、时间和批次。当前这些关系描述不同终点平行样本的条件变化，适合预测群体状态或状态分布；单细胞测量则通过条件分布比较组织。

## 7 为结果可信度安排的具体检查

### 身份与数值

保留稳定ID、原名、原始结构和单位；同名候选经身份复核后入组。保留结构差异与缺失的处理记录。浓度插值存曲线范围和误差，精确浓度结果单独报告。

### 表达与功能质量

表达基础检查包括数值有效性、`-666`等缺失标记、重复与对照；另按重复一致性和TAS分层评价。弱表达响应作为一种可能的真实观测保留，与技术失败区分。

功能值保留原范围：相对数量或活性可以高于1，相对净增长可以为负。根据具体读数选择输出变换和损失，并在原量纲评价。GDSC按官方`gdscIC50`处理流程保留板级正负对照、背景和QC；PRISM保留发布者的标准化、身份质检和筛选批次。[Sanger官方处理说明](https://depmap.sanger.ac.uk/documentation/datasets/drug-sensitivity/)

### 分组与数据划分

核心队列建议先做按药物留出的交叉验证，再做化学骨架留出和五细胞的逐细胞留出。随机条件划分用于补充参考。相同药物及骨架、同一曲线、重复孔、同孔细胞和跨发布重复来源，按对应验证目标一起分组。

当测试目标为未见药物时，表达和所有功能任务都执行同一药物留出规则；整细胞留出也跨任务一致执行。若预训练使用了更大表达或CCLE数据，记录测试细胞、药物是否出现于预训练。

标准化、特征选择、批次校准和模型拟合的参数在训练部分确定。评价剂量外推或插值时，先留出浓度点，再仅用训练浓度拟合用于训练标签的曲线；测试评价优先使用留出的实测点。

### 样本计数与终点权重

同时报告细胞数、药物数、细胞—药物组合数、条件数、独立曲线数、重复数和单细胞数。一个72h功能终点可以关联两个表达时间，但功能损失按其独立终点计权；单细胞表达按实验层级聚合后，再关联群体功能读数。

| 3 | 对核心表达做重复与对照质量检查，提取固定基因顺序的矩阵 | 矩阵、基因表、观测表、质量分层和最终核心入组清单 |
| 4 | 冻结跨任务划分，建立表达单任务、功能单任务及联合基线 | 统一fold清单与可比的基线结果 |

信息分解部分的第一步建议定义为“功能相关成分与剩余表达成分”的统计问题，控制细胞背景、剂量、时间和实验来源后，在留出数据上检验增益。然后再比较潜在共享/特异分支与JEPA辅助目标，依据数据验证选择实现。
