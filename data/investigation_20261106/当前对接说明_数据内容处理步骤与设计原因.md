# 当前对接的数据内容 处理步骤与设计原因

更新日期：2026年11月6日。本说明按数据本身、实际完成情况、处理过程、设计理由的顺序展开。当前HMS核心线的最新产物是[v2库板来源核对目录](../integration_20261106/v2_库板来源核对/)。

## 1 现在有哪两条对接线

**核心线：CCLE背景 + LINCS Phase II表达 + HMS计数。** 目的在于组织同一LJP项目、相同细胞与给药条件下的表达和功能观测。这里已经读取了实际表达矩阵、汇总了计数，并生成可追溯的对应表。

**扩展线：LINCS Phase I/II实验说明 + CTRP浓度级功能数据。** 目的在于扩大可关联的细胞、药物和剂量范围。目前完成的是候选身份和条件连接，使用了真实CTRP测量值；扩展队列尚未逐条提取表达数值并完成入组质量检查。

GDSC、PRISM等文件已下载并有内容检查；目前还没有建成它们与LINCS的最终对接表。下面先把确实已经参与处理的四类数据讲清楚。

## 2 核心线与扩展线的数据里面具体有什么

### CCLE当前表达文件

`OmicsExpressionProteinCodingGenesTPMLogp1.csv`包含1,673个细胞模型表达行、19,193个蛋白编码基因列。行名是ModelID，列名同时带基因符号和Entrez ID。例如：

`行：ACH-000536；列：EGFR (1956)；值：7.8194`

该值是作者RNA-seq处理流程得到的log2(TPM+1)，描述BT20的细胞背景。`Model.csv`把BT-20、BT20、ACH-000536、CVCL_0178这些身份字段连起来。默认profile和全部profile说明表记录模型与分子测量的对应。

本轮使用的是作者已经处理好的表达表。我们按ModelID选择细胞、按Entrez ID选择基因，没有重做RNA测序比对。当前已提取五种细胞的978个基因，保存为5×978矩阵。

### LINCS Phase II表达与条件说明

当前Level5发布矩阵包含118,050条签名、12,328个基因列。978个landmark基因是L1000实际测量的代表基因，其他列来自推断。Level5签名是作者计算并综合重复后的差异表达z-score类数值。

我们使用978个landmark列。举例：`LJP006_BT20_3H:G24`这一签名有一组978维表达变化值，其中EGFR约−0.2080、MYC约−1.4653。24h有另一条对应签名和另一组978维数值。

配套表的作用分别是：

- `sig_info`：签名ID、细胞、药物、显示剂量、时间和原实例ID集合。
- `inst_info`：各单次实验的数值剂量、单位、时间、药物样品批次、板号和孔号。
- `gene_info`：基因ID、名称、是否landmark。
- `pert_info`：药物ID、名称、SMILES、InChIKey等。
- `sig_metrics`：信号及重复一致性指标。

Level3另保存345,976条归一化表达记录，包含处理和参照。它适合进一步核查同平台表达与vehicle参照，目前已用于MCF10A对照追查。核心线当前的表达标签来自Level5。

### HMS三个计数文件

三个文件分别为`Screen20237`、`Screen20238`、`Screen20239`的processedData Excel，对应三个生物重复。每份的Meta工作表说明实验，Data Columns说明字段，Data保存作者成像处理后得到的计数与派生量。

三份共36,912条孔级记录。每行记录细胞、药物、浓度、库板、技术重复、实验板、孔号、72h终点，以及给药开始时参考计数、处理后计数、DMSO对照参考计数。

重要字段有：

| 字段 | 意义 |
|---|---|
| CellLine | 细胞名称，如BT20 |
| BRDid | 作者提供的Broad药物ID |
| Small Mol Concentration与Unit | 给药浓度及单位 |
| LJP Library Plate | 药物库布局，当前为LJP5或LJP6 |
| Barcode、Replicate、Assay Well | 实验板、技术重复和孔位置 |
| Timepoint | 这批文件为72h |
| Relative Cell Count | 处理终点计数/对照参考终点计数 |
| Relative Growth Rate After Treatment | 本地数值对应相对净增长(Nt−N0)/(Nc−N0) |

这些是作者从成像中处理得到的计数表。我们没有重新进行图像分割，而是核对表中比例与计数，再保留重复层级汇总标签。

### CTRP浓度级数据

本轮扩展使用2015原始发布包的`v20.data.per_cpd_post_qc.txt`。该表6,171,005行，字段包括实验ID、化合物ID、浓度、聚合实测相对活性、曲线拟合值及误差量。

这里使用`cpd_avg_pv`作为原测量经作者处理后的汇总值；`cpd_pred_pv`另保留为作者拟合值。实验说明表把experiment_id连到细胞ID，药物说明表把master_cpd_id连到Broad ID及结构。相对活性来自ATP相关检测，原协议为72h给药。

当前扩展已另存49个明确命名的固定比例组合。其余条目进入单药身份候选核查。实验ID在说明表中有重复行，我们只去重已确认不冲突的“实验ID—细胞ID”映射，原日期和其他元数据仍保存在源文件中。

## 4 核心线具体怎样连接

### 第一步从作者HMS表保留观测身份

每条孔记录保留源文件、Excel行号、库板、细胞、药物ID、浓度、实验板、孔号和技术重复。源文件区分三个生物重复，文件内Replicate区分技术重复。

库板LJP5与LJP6统一命名为LJP005和LJP006，用于与LINCS签名中的库板代码核对。这里的库板是化合物库布局；检测板、成像板的实际barcode仍各自保存。

### 第二步在库板内汇总功能

先按“库板、细胞、药物、剂量、生物重复文件”汇总技术孔，分别计算相对数量与相对净增长均值。再对同库板、同条件的三批生物重复等权平均，保留各批值及批间标准差。

为何分两层：原数据中，12,072个库板—生物重复条件有三个技术孔，348个有两个技术孔。按全部孔直接混合平均，会使技术孔较多的批次得到更高权重。先批内、再批间平均，使每批生物重复贡献相同。

各批的相对数量沿用作者表中已经归一化的数值。三批对照参考计数可以不同，先按各自对照形成相对量，再汇总，保留其参照意义。

### 第三步按同库板和数值条件连接表达

v2使用以下连接键：

`LJP库板 + 细胞身份 + Broad药物ID + 数值剂量`

表达时间分别为3h、24h，功能时间为72h。签名中的原实例还用于核对数值剂量、单位、时间、细胞、药物及样品批次。

为何增加库板：前版只按LJP前缀和给药条件找候选，带入78条其他库板的MCF7签名。v2按HMS原文件实际出现的两套库板对应；其他签名另行保存为扩展候选。

进一步说，同一给药条件在不同库板中的功能值也有区别。例如BT20、GSK-1059615、0.04 μM，LJP005的相对数量均值约1.00550，LJP006约0.88385。差异的具体原因尚需核查；v2先保留库板及各自重复，之后用对照、来源和批次信息分析差异，再决定最终汇总方式。

### 第四步读取与统一基因

用签名ID在Level5定位表达行，按gene_info中的实测landmark标记选择978个基因。用Entrez ID将这978个基因与CCLE列对应，并在两个导出矩阵中使用同一顺序。

这样做是为了让输入和输出的基因身份一一对应。CCLE背景值与L5变化分数各自保留量纲，后续在训练划分内分别拟合标准化参数。

### 第五步形成条件记录与矩阵索引

一条库板条件记录保存细胞ModelID、药物结构、剂量、3h/24h签名ID、72h功能、重复及质量字段。另保存独特的细胞—药物—剂量组ID，把同一条件的两个库板放在同一组。

第一版可将一个条件的两个表达时间作为两个表达目标，把72h功能作为一个终点。关系表可按时间展开；功能端权重归一到同一个终点，后续划分也按所评估的药物、细胞或条件组统一执行。

## 5 真实例子是怎样的一整条记录

| 部分 | 实际内容 |
|---|---|
| 库板和条件 | LJP006；BT20；afatinib；0.04 μM |
| 细胞身份 | BT-20 / BT20 / ACH-000536 / CVCL_0178 |
| 细胞背景 | CCLE中ACH-000536的978维表达 |
| 药物身份 | BRD-A58767537；保留药物结构和实例样品批次 |
| 3h表达 | LJP006_BT20_3H:G24的978维变化分数 |
| 24h表达 | LJP006_BT20_24H:G24的978维变化分数 |
| 72h功能 | 相对数量0.751241；由三个生物重复、每批三个技术孔汇总 |

0.751241的来源是：三批均值0.722953、0.768253、0.762517等权平均。它表征该条件下终点细胞数量约为DMSO对照的75.1%。

连接表达与计数的理由是同项目、同库板、同细胞和药物、同剂量，而非表达值与计数恰好相关。各时间点来自平行实验，CCLE则提供另一次实验中的细胞背景。[原始计数和978基因实例](../integration_20261106/BT20_afatinib_0.04uM实例/逐步说明.md)

## 6 扩展线的真实例子与处理意义

在候选关系Q5890中：

- 细胞为BT20，药物为dasatinib，Broad ID为BRD-K49328571。
- LINCS表达浓度为0.04 μM、时间3h，签名包括LJP005_BT20_3H:D06和LJP006_BT20_3H:I06。
- 对应CTRP曲线为CTRP2015:663:52882，最近实测浓度为0.032 μM，该点相对活性为0.7838。
- 两浓度相差1.25倍，log10差约0.09691。

当前保存的是上述两个真实浓度与其关系。0.7838对应CTRP的0.032 μM测量。若分别训练表达和功能任务，各自使用本次测量的真实浓度；若要构建同一0.04 μM输入下的双标签，需要寻找该浓度实测值，或对功能曲线进行经过误差评估的内插，并标记估计来源。

这解释了为什么要把“相同浓度”“邻近浓度”“曲线内插”分开：三者提供的证据和标签来源不同。

还有一个已发现的身份例子：HMS/LINCS中的afatinib为BRD-A58767537，CTRP的afatinib为BRD-K66175015；结构中立体信息的记录也不同。当前共同Broad ID的试算没有把它们按药名直接合并。后续需核查实际化学实体与样品资料，再决定归并方式。这是当前覆盖属于一条具体候选规则、并非全部可对接范围的另一个原因。

## 7 MCF10A为什么先前没进入这个输入版本

这个问题已经单独追查。ModelID正确，本地CCLE文件与官方MD5一致；固定24Q4的公开profile映射没有为MCF10A提供RNA条目。它的模型身份属于总名录，RNA矩阵则覆盖有相应RNA profile的模型，二者范围不同。

为何该模型未纳入公开RNA profile，上游实验或发布原因未在README中说明。本轮不把这个未知原因解释成数据坏了，或MCF10A没有表达数据。

现在已找到并读取本地295个MCF10A的LJP vehicle表达，另下载并验证四个0h RNA-seq文件。四个文件已汇总到基因TPM，各自数值和来源保留；培养和基因注释复核后再决定如何作为背景输入。独立研究采用的实验培养基与常规生长条件有差别，先核实这一点，再加入队列。[完整原因与补充来源](MCF10A为何缺行_原因追查.md)

因此，当前3,168反映的是固定CCLE输入版本的候选集合。MCF10A另有637个双表达时间齐全的功能条件，正在按新的来源证据研究补齐方式。

## 8 目前怎样设计下一步 为什么

1. **先确定输入所指的状态。** 比较“细胞背景RNA”与“同平台同期vehicle参照”，使状态名称、实验条件与实际测量一致。
2. **先保存库板、重复和对照，再决定最终汇总。** 已经观察到部分库板间读数差异，保留层级便于定位原因和评估可靠性。
3. **把表达与功能作为独立目标。** 前者为978维变化，后者为具体方法下的细胞数量或活性，联合训练检验它们是否提供互补信息。
4. **用核心线验证连接关系，用扩展线增加覆盖。** 同项目条件对应提供清楚的实验关系，跨库数据增加细胞和药物范围，分别评估来源影响。
5. **先冻结分组再训练。** 相同条件的两库板、三批重复、两个时间点共用组ID；药物留出时两个任务同时留出，得到能回答泛化问题的评价。

这些是接下来要实施和检验的选择。当前已完成到真实矩阵和功能表的来源核对、条件组织；最终质量入组、跨库身份复核、统一划分与模型评价仍是明确的后续步骤。
