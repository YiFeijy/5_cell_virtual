# iter-01：最初 v0 数据预处理

本步把 HMS 72h 成像核计数、LINCS GSE70138 的 24h 表达响应和 CCLE/DepMap 24Q4 给药前 RNA 背景，整理成可以直接进入模型的固定队列。**实跑得到 5 株细胞、106 药、3,364 条库板记录、3,133 个不同生物条件；所有训练数组和样本/划分表与冻结版本逐值一致。** 本步没有训练模型，也没有产生新的模型实验结果。

入口是 [run_preprocess_v0.py](run_preprocess_v0.py)，三份实测产物是 [漏斗表](v0_cohort_funnel.csv)、[划分表](v0_split_summary.csv) 和 [完整审计报告](v0_preprocessing_report.json)。当前保留的报告来自原始 L3 与 L5 全量校验模式。

## 1. 思路（Why）

研究问题是：能否从给药前的细胞背景、药物结构与剂量，同时预测给药后的表达变化和细胞数后果。先构建一个来源可追溯的小队列，才能判断后续模型差异是否来自数据处理或划分。

这里的一个训练观测单位是 **库板 × 细胞 × 药物 × 剂量**。同一个细胞、药物和剂量可能出现在两个库板，LINCS 表达签名也有各自的库板来源，所以先在每个库板内汇总 HMS：同批技术孔取均值，再对三批生物重复等权平均。不能把所有孔直接混在一起，因为原始表中 348 个生物重复组只有 2 个技术孔，另 12,072 组有 3 个；直接混合会改变各批权重。

MCF10A（ACH-001357）在身份表存在，但这次 CCLE 24Q4 RNA 矩阵没有其数据行，无法提供模型所需背景，因此剔除。理由是本发布缺 RNA，不能据此断言它在其他版本也没有表达数据。WH-4-025（BRD-U60236422）的原始 `canonical_smiles` 为 `restricted`，无法生成分子指纹，因此剔除；不能用一个全零向量冒充结构。虽然 MCF10A 是非癌上皮，本轮并没有用“是否癌细胞”作为这一步的筛选规则。

24h 表达必须匹配同库板、同细胞、同药物和同剂量。每条签名至少需要两个有效处理实例，并要求其检测板至少有两个有效 DMSO 溶剂对照，才能满足 v0 的基本技术覆盖要求。46 条只有单实例的签名不满足这一条件。这里不按 TAS、表达响应强弱或重复相关系数筛样本，也不把基础数值 QC 称为完整生物学质量验证。

最后以不含库板的 `(cell_id, pert_id, dose_uM)` 定义“生物条件”。同条件若在两块库板都留下记录，每条权重为 `1/2`，只有一块则为 `1`，使每个条件的总权重相同。新药实验按化学组整体留出，新骨架实验按骨架组整体留出，同条件的跨板记录始终同行。标准化参数只从训练部分拟合，避免验证或测试数据参与参数估计。

## 3. 预处理五步漏斗与真实样本追踪（Pipeline & Concrete Trace）

实跑的漏斗如下。原孔到技术/生物重复的汇总是单位转换，不把相减的孔数叫作“剔除样本”；漏斗从 4,140 条库板观测起算。

| 步骤 | 进入记录 | 保留记录 | 剔除记录 | 剩余不同条件 | 具体原因 |
|---|---:|---:|---:|---:|---|
| 1. HMS 汇总 | 4,140 | 4,140 | 0 | 3,852 | 36,912 孔先变为 12,420 条批内均值，再等权汇总三批 |
| 2. RNA 背景与结构 | 4,140 | 3,420 | 720 | 3,180 | MCF10A 缺 RNA 690 条；再剔除其余细胞 WH-4-025 的 30 条 |
| 3. 同库板 24h 表达 | 3,420 | 3,410 | 10 | 3,171 | 原始 `sig_info` 无对应 24h 签名 |
| 4. L3 实例与对照 QC | 3,410 | 3,364 | 46 | 3,133 | 46 条单实例签名；没有额外数值或对照不足剔除 |
| 5. 权重、特征与划分 | 3,364 | 3,364 | 0 | 3,133 | 完成精确核对，不再筛选 |

第二步按原因分别计数时：缺 RNA 为 **690 记录 / 642 条件**，结构受限为 **36 / 36**，两者重叠 **6 / 6**，所以并集为 **720 / 672**；只缺 RNA 是 **684 / 636**，只缺结构是 **30 / 30**。不能将 690 与 36 直接相加。

第三步还检查了缺失的原始记录：8 条只有同条件的 3h 签名，另外 2 条是 LJP006 的 AZD-8055 10 uM（MDAMB231、SKBR3），在该库板下连同条件的其他时间签名也没有。完整 ID、细胞和剂量列在 JSON。可以确定是本发布原始 `sig_info` 无匹配，不是本脚本遗漏提取；具体上游缺失原因未公开，不能擅自写成 QC 失败。

第四步的 10,512 个处理实例全部有限且无 `-666`，799 个 DMSO 对照也全部有效；32 块检测板各有 23–26 个有效对照。有效性只检查 978 个实测 landmark，忠实采用 `src/prepare.py` 的范围。入组签名分别有 2 / 3 / 4 个有效实例，对应 **244 / 2,502 / 618 条记录**。至少两个实例的要求不是对新药反应强弱作筛选。

第五步有 **2,902 个单板条件 / 2,902 条记录**，**231 个双板条件 / 462 条记录**；因此 `2902×1 + 462×0.5 = 3133.0`。最终队列不是完整的 `5×106×6` 笛卡尔积。

以 **BT20 + afatinib（BRD-A58767537）+ 0.04 uM，LJP006** 为例：

| HMS 生物重复文件 | 技术孔的相对计数 | 技术孔均值 | 相对净增长均值 |
|---|---|---:|---:|
| `Screen20237_LJP_processedData1.xls` | 0.72162、0.75050、0.69674 | 0.722953333333333 | 0.603596666666667 |
| `Screen20238_LJP_processedData2.xls` | 0.72427、0.82928、0.75121 | 0.768253333333333 | 0.650926666666667 |
| `Screen20239_LJP_processedData3.xls` | 0.72555、0.78259、0.77941 | 0.762516666666667 | 0.665003333333333 |

三个文件都对应 Excel 第 2–4 行。第一批 `N0=1657.7396`、`Nc=5505.6667`，三个处理孔 `Nt=3973/4132/3836`；其他两批的完整原孔计数也在 JSON。v0 使用工作簿已发布、已取小数的相对指标列求均值，不能用 `Nt/Nc` 重除来替换这些列，否则会悄悄改变冻结标签。

三批等权结果为 **相对细胞数 `0.7512411111111111`（展示为 `0.7512411`）**，相对净增长 `0.639842222222222`；库板条件哈希是 `HMSv2_LIB_175ffaa50568acca`，不含库板的条件组是 `HMSv2_COND_a8478233af7ce101`。

该条件通过背景与结构过滤：BT20 对应 `ACH-000536`、`cell_index=3`，afatinib 对应 `drug_index=7`，Morgan 有 74 个置位；`log10_dose_uM=-1.3979400396347046`。前五个基因为 `780, 7849, 6193, 23, 9552`，背景分别为 `7.621172904968262, 1.5210506916046143, 9.868621826171875, 6.510962009429932, 6.136683464050293`。

表达对应 `LJP006_BT20_24H:G24`，其三个实例是 `LJP006_BT20_24H_X1_B17:G24`、`..._X2_B17:G24`、`..._X3_B17:G24`；同板有效 DMSO 数依次为 **25、26、25**。三个实例都通过 QC，归档的对照中心化重复相关中位数为 `0.367689364677753`。前五维 24h 响应为 `0.28653478622436523, -0.9907945990562439, -1.1542381048202515, 0.3489273488521576, 0.5902959704399109`。

最终该条为 **`sample_index=311`、`condition_weight=1.0`**。在 unseen_drug 第 0 折为 validation，第 1 折为 test，第 2–4 折为 train；在 unseen_scaffold 第 3 折为 validation、第 4 折为 test，其余为 train；剂量外推中为 train。该行进入哪个角色完全由分组规则与剂量确定，与它的两个响应标签无关。

## 4. 代码与手动复现方法（Code）

脚本的五个阶段分别是 `stage1_hms`、`stage2_inputs`、`stage3_expression`、`stage4_qc`、`stage5_assembly`。`extract_gctx` 逐批读取 HDF5；`assign_folds` / `make_splits` 重建划分；`exact_frame` 检查完整表格的列顺序、行顺序、dtype、缺失位置和每个数值。任一检查失败都会报错退出，只有全部通过才写三份审计产物。

依赖为 Python 3.10+、numpy、pandas、h5py、rdkit、xlrd。版本对应仓库 `requirements.txt` 和 `requirements-data.txt`；本次指定的 `/home/data2/jiangyun/envs/Rdpy310/bin/python` 实际版本为 Python 3.12.12，其他版本为 numpy 2.0.1、pandas 2.3.3、h5py 3.16.0、RDKit 2025.09.4、xlrd 2.0.2。缺少 Excel 依赖时脚本会提示 `pip install xlrd`，代码没有写死本机 wheel 路径。

从仓库根目录运行全量模式：

```bash
python iterations/01_v0_preprocessing/run_preprocess_v0.py
# 大矩阵在其他位置时，参数是其 LINCS_GSE70138 子目录的上一层：
python iterations/01_v0_preprocessing/run_preprocess_v0.py --unpacked-root /path/to/unpacked
```

默认先寻找 `REPO_ROOT.parent/data/unpacked`，再寻找 `REPO_ROOT/data/unpacked`。本次实际读取前者的 17,072,655,504 字节 Level 3 与 5,824,120,558 字节 Level 5。HDF5 的 `META/COL/id` 对应矩阵行（签名/实例），`META/ROW/id` 对应矩阵列（基因），每 256 行读取后按固定 978 基因取列。所谓“全量”是把本队列所有需要的行和实测基因全部核对，不是扫描发布矩阵中所有其他细胞/基因。

全量 L3 缺文件时直接失败并提示路径或轻量参数，不会静默冒充成功。L5 存在时完整核对全部候选；L5 缺失时明确报告 `archived_reference_expression`，因此只有同时出现 `l3_verification_mode=full_raw_l3_gctx` 和 `stage3.L5.raw_verified=true` 才表示本次的 L3+L5 均已原始核对。

新克隆没有 GCTX 时的轻量命令：

```bash
python iterations/01_v0_preprocessing/run_preprocess_v0.py --skip-l3-gctx
```

此模式跳过两个大 GCTX，仍从 HMS 原孔重算，从原始 LINCS 元数据重建实例引用与 DMSO 板对应，再交叉核对三张归档 QC 表。报告明确写 `l3_verification_mode=archived_qc_tables`，不会声称重新检查了 L3 数值、L5 响应或重算重复相关系数。运行会覆盖本目录同名三份报告，需再次运行全量模式才能恢复完整原始核对报告。

需要另存实际重建数组及表格时：

```bash
python iterations/01_v0_preprocessing/run_preprocess_v0.py --write-rebuilt-dir /tmp/v0-rebuilt
```

这会额外写 `arrays.npz`、`samples.csv`、`splits.csv`，并读回核对。仓库内的输出仅允许本迭代目录，禁止覆盖 `data/` 等冻结目录；默认不产生这些大文件。

划分完全采用冻结规则：先按不同生物条件数对药物组/骨架组降序排序，数量相同用 `sha256('20261107|group')` 升序排序；逐组分配给当前负载最小的折，同负载选择编号最小折。第 `f` 折的 test 是组分配为 `f` 的记录，validation 是 `(f+1)%5`，其余 train。剂量外推是 `<=1.11 uM` train、`3.33 uM` validation、`10.0 uM` test。

每个协议、每一折都检查不同角色之间的生物条件组不交叉；unseen_drug 另查化学组、unseen_scaffold 另查骨架组。剂量外推允许同一药物出现在三个角色，这是已知药物的高剂量预测任务，仍不允许同一个具体细胞/药物/剂量的跨板记录分散到不同角色。

标准化规则对应 `src/train.py`：以训练记录的 `condition_weight` 求 `mu=sum(w*x)/sum(w)` 和 `sigma=sqrt(sum(w*(x-mu)^2)/sum(w))`。背景按样本索引展开后逐基因标准化，标准差下限 `1e-4`；log10 剂量和 count72 分别加权标准化；验证和测试复用训练参数；功能预测再逆变换。Morgan 保持二值，Level 5 响应保持原 z-score。磁盘上的六个核心数组全部保留原尺度，脚本只逐折演示并记录参数，不把标准化后的数组覆盖回去。
