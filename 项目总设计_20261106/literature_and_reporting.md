## 1 与当前研究最接近的工作

| 原始工作 | 实际数据连接与标签 | 本项目的具体对照和判断 |
|---|---|---|
| [Niepel等2017](https://doi.org/10.1038/s41467-017-01383-w) | 同项目L1000与平行细胞计数，研究表达与生长关系 | HMS是当前主实验的直接数据基础；逐字段确认本地读数，而不是将论文中的GR概念直接套到本地净增长列 |
| [Szalai等2019](https://doi.org/10.1093/nar/gkz805)及[原始预处理](https://github.com/bence-szalai/Cell-death-signatures/blob/master/code/cell_death_1_preprocess.ipynb) | LINCS按细胞、Broad ID连接CTRP最近剂量，log10差<0.2；研究死亡相关表达 | 已有近剂量关联的直接先例；本地保留两侧真实剂量，对比严格、近剂量、估计和缺标签监督 |
| [MIX-seq2020](https://doi.org/10.1038/s41467-020-17440-w)及[作者代码](https://github.com/broadinstitute/mix_seq_ms) | 单细胞表达按细胞系归属，与GDSC/PRISM AUC敏感性关联，研究活性相关/无关表达变化 | 表达与功能的关联分解已有人研究。需要复现统计分解并比较未见实体和跨实验稳定性；作者sens不作新增独立功能真值 |
| [MultiDCP2022](https://doi.org/10.1371/journal.pcbi.1010367) | 异构表达与功能任务联合学习；功能曲线拟合后计算目标剂量标签 | 双任务框架的重要直接比较对象；本项目主实验保留实际剂量功能读数，扩展区分实测与估计。不能宣称首次联合预测表达与活性 |
| [scTherapy2024](https://doi.org/10.1038/s41467-024-52980-5) | LINCS表达与PharmacoDB剂量曲线关联，在目标剂量插值 | 设置曲线内插值基线，并用遮盖实测点评价插值误差；患者转用的结论与本项目细胞系证据范围分别解释 |
| [TranSiGen2024](https://doi.org/10.1038/s41467-024-49620-3) | 学习处理/参考表达的表示并用于下游任务 | 与同平台L3参考路线、普通表示预训练比较；背景与响应尺度需一致定义 |
| [SequenTx2026](https://doi.org/10.1038/s42256-026-01192-1) | LINCS、CTRP支持状态/功能模型，并结合独立实验研究序贯策略 | 状态转移与功能串联已有直接工作。我们的单药结果若成立，可证明对应单药任务；序贯主张需相应轨迹和验证 |
| [Hafner等GR方法2016](https://doi.org/10.1038/nmeth.3853) | 用初始/终点计数校正细胞分裂差异 | HMS有N0可进一步复现GR；需另立计算列、标注定义，并说明它与净增长均源于相同计数，不能互称独立验证 |
| [sci-Plex2020](https://doi.org/10.1126/science.aax6234)、[scPerturb](https://doi.org/10.1038/s41592-023-02144-y) | 单细胞表达、条件和部分丰度代理；统一格式继承原实验 | 外部表达方向/时间/异质性；只有实际独立功能测量的条件才进入独立功能评价 |

关于MultiDCP的方法，对照依据包括其Cell viability prediction dataset和架构章节。对本项目的判断是：与其比较时既要做同数据的模型比较，也要做“原始剂量标签/曲线估计/不完整重叠”的数据策略比较，避免把数据差异算作架构收益。

SequenTx原始论文发表于2026年Nature Machine Intelligence，第8卷351–371页。论文当前Code availability链接为[DELTA-TJ/SequenTx](https://github.com/DELTA-TJ/SequenTx)；此前本地代码摘录来自仍可访问的[bm2-lab/SequenTx](https://github.com/bm2-lab/SequenTx)。复现时锁定实际下载仓库与commit；本轮只核对两个入口及论文链接，没有宣称二者所有内容逐字相同。

更广研究清单及已读代码路径见[原文献调研](../数据可行性调研_20261105/literature_review.md)。本轮只更新与整体设计直接有关的判断；未实际重跑上述作者模型，不把文献报告的分数写成本项目对照结果。

## 2 当前最值得检验的贡献

可以检验的贡献包括：一套保持实验语义和来源的表达—功能基准；不同泛化条件下共同监督的增益或负迁移；早期实测相对纯计算预测的价值；在重复、剂量、时间和跨平台变化下仍可复现的关联分量。

这些都还是研究问题。要形成方法贡献，必须在同样信息预算下优于强基线，并用消融指出哪项设计产生收益；若主要贡献是数据和实证分析，就准确报告数据复核、可靠性、可重现结论与适用范围。不能把添加一个JEPA损失或共享/专属分支本身等同于已证明的新科学结论。

## 3 NC规范：来源与我们的选择分开

用户尚未确认本轮“NC”的具体期刊及正文版本。下表暂按Nature Communications官网列出，收到具体信息后对照适用版本；没有把个人建议写成编辑意见。

| 类型 | 可核查要求/建议 | 本项目落实 |
|---|---|---|
| 正式数据政策 | 原创研究需数据可用性声明；说明支撑结论的最小数据及复用数据的accession/标识，披露限制 | 清单、版本、URL、哈希、来源实验、处理矩阵、条件级预测和图源数据；大原始数据引用公开仓库 |
| 代码/复现政策 | 必要材料、代码和协议应可供核查；计算研究提交资源强调代码和可复现方法 | 版本锁定、环境、脚本、划分、配置、日志、随机种子和复现命令；正式提交时核对自定义代码清单 |
| 资源身份报告 | 官网强调细胞系来源及鉴定和持久身份标识 | 保存源细胞名、ModelID、RRID/Cellosaurus及鉴定状态；公共数据重用按作者记录，不声称重新做过STR |
| 本项目设计选择 | 五折、3个起始种子、药物组bootstrap、预定主要终点及具体误差指标 | 为回答泛化和重复性问题设置，写入方法；没有发现上述具体数量是NC统一硬性规定 |
| 需正文材料才能落实 | 稿件主张、编辑意见、审稿实验要求 | 正式正文及对应意见提供后逐条建证据映射；本轮初步方案不冒充正文 |

## 4 正文与现有结果怎样纳入

当前可确认的原始研究文件是根目录初步方案与图。主张已整理为[claims_evidence.csv](claims_evidence.csv)，包括当前证据、拟检验实验及结论升级条件。已有描述性相关来自历史v1时须明确版本；本轮v3重复审计不是模型准确率。

正式正文接入后逐句核对任务、输入、终点、样本单位和实际训练结果；支持的保留，冲突的指出具体原因及影响，证据缺口对应补充实验。正文、用户看法、文献与我们的设计都按同一证据标准接受检验。
