# 03 怎样对接成训练样本

贯穿下面步骤的真实例子是：**BT20＋afatinib＋0.04 μM，LJP006库板**。给药条件相同是建立关系的起点；同时保留表达24h、计数72h和不同实验的来源。

**第一步：先从功能原孔形成答案。** 在每个HMS生物重复文件内，按“库板＋细胞＋药物ID＋实际剂量”汇总技术孔，再等权平均三批。早期曾形成较宽的细胞/药物/剂量候选，随后追查库板来源，将LJP005/006纳入键后重新汇总；当前训练使用的是保留库板的版本。这个例子三批均值为0.7229533、0.7682533、0.7625167，得到72h功能答案**0.7512411**。保留三批值与原Excel行号，读者可以重算。[本例重复与原孔引用](../examples/sample_311/72h原始功能重复及孔引用.csv)

**第二步：在表达表里找对应条件。** 药物ID为`BRD-A58767537`，24h签名为`LJP006_BT20_24H:G24`，并追到三个原实例。匹配同时检查库板、细胞、药物和数值剂量，而不是只凭药名找一条相近记录。Level5中提取978个实测基因的响应，作为表达答案。

**第三步：补给药前输入。** BT20按身份ACH-000536取CCLE背景；afatinib按结构生成2048位Morgan指纹，以固定的结构特征先建立可复现比较起点；剂量保留μM，输入取log10(0.04)，将倍数浓度差转换到连续尺度。背景矩阵、表达目标和基因ID全部按同一978基因顺序排列。CCLE的log2(TPM+1)和LINCS的z响应各保留原含义。

**第四步：查原实例和对照再入组。** 本轮检查了10,512条处理实例引用、799个同板对照。要求身份、剂量、24h及单位一致，978值有限且非−666，每条签名至少2个有效实例、对应板至少2个有效溶剂对照。没有按表达强弱挑样本。46条单实例签名留在排除原因表，最终形成下面的数据流：

| 经过哪一步 | 库板观测数 | 不同细胞＋药物＋剂量条件数 | 为什么这样处理 |
|---|---:|---:|---|
| HMS功能条件，保留库板来源 | 4,140 | 3,852 | 先保留原实验来源 |
| 有当前背景表达且药物结构可解析 | 3,420 | 3,180 | 满足本轮统一输入定义 |
| 有对应24h表达 | 3,410 | 3,171 | 同时具备本轮两类答案；不要求3h也存在 |
| 通过上述基本实例/对照检查 | **3,364** | **3,133** | 作为本轮冻结比较数据 |

**第五步：保留重复关系用于训练与评价。** 同条件跨库板出现时，每条观测权重为1/该条件库板数，合计为1；划分时也整体放到同一组。这样既保留来源差异，又控制重复条件的权重。最后是5种细胞、106药，BT20/HS578T/MCF7/MDAMB231/SKBR3分别有629/624/634/622/624个不同条件。

这一阶段的产物是[samples.csv](../data/training/samples.csv)、[arrays.npz](../data/training/arrays.npz)和[划分表](../data/training/splits.csv)。前者让人读条件，第二个保存真正的数字，第三个说明每条用于训练、验证还是测试。对应处理代码为[库板汇总](../src/aggregate_hms.py)和[本轮入组与数组整理](../src/prepare.py)，数量见[入组流程表](../data/training/cohort_flow.csv)。

仍看BT20＋afatinib＋0.04 μM：给药前背景、结构、剂量进入模型；实测答案为24h的978维响应和72h的0.7512411。附带的一个新药测试折模型预测细胞数为0.8065399。这条记录用来理解数据到预测的过程；整体性能由[结果页](05_results.md)的完整测试评价。
